# 题库格式规范

每个方向一个 JSON 文件，位于 `questions/<slug>.json`。

## 文件结构

```json
{
  "direction": "JavaScript 基础",
  "slug": "javascript-basic",
  "questions": [
    {
      "id": "javascript-basic-001",
      "title": "简述 var / let / const 的区别与提升机制",
      "difficulty": "中等",
      "type": "简答",
      "question": "详细说明 var、let、const 在作用域、变量提升、重复声明、循环闭包上的差异。",
      "answer": "（Markdown 文本，支持 \\n 换行、**加粗**、`行内代码`、```代码块```）",
      "keywords": ["var", "let", "const", "块级作用域", "变量提升", "TDZ"],
      "repoRefs": ["src/utils/utils.ts"]
    }
  ]
}
```

## 字段规则

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 唯一，格式 `<slug>-<三位序号>`，如 `javascript-basic-001` |
| `title` | 是 | 一句话概括考点，不超过 40 字 |
| `difficulty` | 是 | 只能是 `简单` / `中等` / `困难` |
| `type` | 是 | 只能是 `简答` / `单选` / `不定项` / `填空` / `编程` |
| `question` | 是 | 完整题干。可含换行。 |
| `answer` | 是 | 完整答案。Markdown。要讲清「为什么」，不能只罗列结论。 |
| `keywords` | 是 | 3-8 个关键知识点，用于检索与标签展示 |
| `repoRefs` | 否 | 仓库内相关文件路径（相对 `/workspace`），仅在该题确实能结合本仓库代码时填写 |

## 质量要求

1. **题目必须是前端题目**，不要后端、算法、操作系统类内容。
2. **答案要有深度**：说明原理、边界条件、常见坑，而不是"因为 X 所以 Y"。
3. **难度分布**：每个方向内 简单 ≤ 2 题，中等 ≥ 4 题，困难 ≥ 1 题。
4. **类型分布**：以 `简答` 为主（≥ 60%），其余可适当穿插 `单选`/`不定项`/`填空`/`编程`。
5. **不重复**：同一个方向内考点不要重叠；跨方向可有关联但角度须不同。
6. **编程题**：`answer` 中给出完整可运行代码 + 复杂度分析。
7. **单选/不定项题**：`question` 中必须包含选项列表，格式为每行一个选项，以 `A. ` / `B. ` 开头；`answer` 开头用 `答案：A` 的形式给出并说明理由。
8. **填空题**：`question` 中用 `____` 表示空缺，`answer` 中用 `A. xxx` 形式列出每个空的答案。
9. `repoRefs` 只填真实存在的文件路径，填写前请用 Read/Glob 确认。

## 反例

- ❌ "简述 JavaScript" —— 考点太宽。
- ❌ 答案只有一句结论没有原理说明。
- ❌ 编造不存在的仓库文件路径。
