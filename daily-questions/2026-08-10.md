## 一、HTML / 语义化（2 题）

### 1. 说说 `<!DOCTYPE html>` 的作用是什么？去掉会怎样？
**参考要点**
- 作用：声明文档类型，触发浏览器按 **标准模式（Standards Mode）** 解析页面，而不是切换到混杂模式（Quirks Mode）。
- 去掉后果：浏览器会进入怪异模式，盒模型、布局、样式表现都与现代标准不一致，常出现 IE5.5 时代的兼容行为。
- 历史：HTML5 之前声明较复杂（指向 DTD），HTML5 简化为 `<!DOCTYPE html>` 即可。

### 2. `<script>` 的 `defer` 和 `async` 有什么区别？应该怎么选？
**参考要点**
- **普通 script**：阻塞 HTML 解析，下载完立即执行。
- **defer**：异步下载，**等到 DOM 解析完毕、`DOMContentLoaded` 之前**按顺序执行，多个 defer 按出现顺序执行。
- **async**：异步下载，下载完立即执行，**不保证执行顺序**，谁先到谁先跑。
- 选择：依赖 DOM 或多个脚本有顺序要求 → `defer`；独立脚本（如统计、监控）→ `async`。

## 二、CSS / 布局（2 题）

### 1. 详细说一说 CSS 中的 BFC（块级格式化上下文），它能解决哪些实际问题？
**参考要点**
- 形成条件：根元素、`float` 不为 none、`position: absolute/fixed`、`display: inline-block/table/flow-root/flex/grid`、`overflow` 不为 visible 等。
- 特性：内部盒子垂直排列、外边距折叠、不会与浮动元素重叠、可以包含浮动子元素。
- 典型应用：清除浮动（`overflow: hidden`）、阻止外边距合并、两栏自适应布局（`overflow: hidden` + 浮动）、解决高度塌陷。

### 2. 介绍一下 Flex 布局中 `flex: 1` 的完整含义，它和 `flex: auto`、`flex: none` 有什么区别？
**参考要点**
- `flex: 1` ≡ `flex: 1 1 0%`：放大 1、缩小 1、基础尺寸 0。
- `flex: auto` ≡ `flex: 1 1 auto`：基础尺寸为内容大小。
- `flex: none` ≡ `flex: 0 0 auto`：不放大、不缩小、保持内容尺寸。
- 关键差异在于 `flex-basis`：使用 0% 时各 item 平分剩余空间；用 `auto` 时按内容比例分配。

## 三、JavaScript 基础（3 题）

### 1. `var`、`let`、`const` 的区别是什么？暂时性死区是什么？
**参考要点**
- `var` 函数作用域、有变量提升、可重复声明、挂到 window。
- `let` / `const` 块级作用域、无提升（但有创建阶段）、同一作用域不可重复声明、不挂到 window。
- **TDZ（Temporal Dead Zone）**：`let/const` 声明前访问会抛 `ReferenceError`，从块开始到声明语句之间即为 TDZ。
- `const` 声明的是绑定不可变，对象/数组的引用不可改，但属性可以改。

### 2. 说说原型链和继承，写一下 `class` 的继承实现
**参考要点**
- 每个对象都有 `__proto__`，指向其构造函数的 `prototype`；`prototype` 上挂的方法可通过 `__proto__` 被所有实例访问。
- 查找属性时沿 `__proto__` 一路向上，直到 `Object.prototype.__proto__ === null`。
- ES6 `class` 本质是构造函数 + 原型继承的语法糖，`extends` 内部通过 `Object.setPrototypeOf(Sub, Super)` 建立原型链，`super()` 调用父类构造函数。

```javascript
class Animal {
  constructor(name) { this.name = name; }
  speak() { console.log(this.name + ' makes a noise.'); }
}
class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
  speak() {
    super.speak();
    console.log(this.name + ' barks.');
  }
}
```

### 3. 说说事件循环（Event Loop）中宏任务和微任务的执行顺序
**参考要点**
- 任务分：宏任务（script、setTimeout、setInterval、I/O、UI 渲染）和微任务（Promise.then、queueMicrotask、MutationObserver）。
- 执行流程：执行一个宏任务 → 清空当前微任务队列 → 渲染（如果需要）→ 取出下一个宏任务。
- 典型输出题：`setTimeout(() => console.log(1), 0); Promise.resolve().then(() => console.log(2));` 结果是 2, 1。
- Node 中还有 `process.nextTick` 和每个阶段之间的微任务队列，要区分浏览器模型。

## 四、TypeScript（2 题）

### 1. `interface` 和 `type` 的区别？什么场景下用哪个？
**参考要点**
- `interface` 专注描述**对象/类的形状**，支持**声明合并**、可被 `extends`/`implements`。
- `type` 是**类型别名**，能表达任意类型（联合、交叉、映射、工具类型），不支持声明合并。
- 选择：定义对象/类契约时优先 `interface`；需要联合/交叉/工具类型组合时用 `type`；在团队规范里保持一致即可。

### 2. 解释 `any`、`unknown`、`never` 三个顶级类型的区别
**参考要点**
- `any`：绕过类型检查，可赋值给任何类型，也可被任何类型赋值（不推荐使用，会丧失类型安全）。
- `unknown`：安全版的 `any`，**只能赋值给 `unknown` 或 `any`**，使用前必须做类型缩窄。
- `never`：表示"永远不会出现的值"，常用于穷尽检查（`switch` 的 `default: const _: never = x`）。

## 五、React（3 题）

### 1. React 中 `useEffect` 和 `useLayoutEffect` 的区别？什么场景必须用 `useLayoutEffect`？
**参考要点**
- `useEffect`：在浏览器**绘制之后**异步执行，适合数据请求、订阅、埋点等无副作用视觉的场景。
- `useLayoutEffect`：在 DOM 更新后、**浏览器绘制之前**同步执行，会阻塞渲染。
- 必须用 `useLayoutEffect` 的场景：DOM 测量（如 `getBoundingClientRect`）、防止闪烁的样式同步、基于 DOM 的动画初始化。

### 2. React 的 Fiber 架构解决了什么问题？时间分片（Time Slicing）是如何实现的？
**参考要点**
- 旧架构 Stack Reconciler 是递归、同步、不可中断的，大型组件树会阻塞主线程。
- Fiber 将渲染拆成可中断的链表节点（child/sibling/return），通过 `requestIdleCallback`（React 18 用 scheduler 包）实现时间分片，浏览器有空时执行。
- 双缓存：构建 `workInProgress` 树，提交时一次性替换，保证一致性。
- 优先级机制：不同更新分配不同 lane（transition、sync 等），高优先级任务可打断低优先级。

### 3. React 18 的 `Suspense` 配合 `lazy` 是怎么实现代码分割的？
**参考要点**
- `React.lazy(() => import('./Other'))` 返回一个包含动态 `import` 的组件，首次渲染会触发该 chunk 的网络请求。
- 加载期间抛出 Promise，`Suspense` 捕获后展示 fallback UI，加载完成后再渲染真实组件。
- 配合 React 18 的 `useTransition` 可以让"非紧急更新"在加载期间保持旧 UI 可交互，避免 loading 闪烁。

## 六、Vue（3 题）

### 1. Vue 2 和 Vue 3 的响应式原理有什么区别？
**参考要点**
- Vue 2：`Object.defineProperty` 劫持每个属性的 getter/setter，无法监听新增/删除属性（需 `Vue.set`/`Vue.delete`）和数组下标。
- Vue 3：`Proxy` + `Reflect`，能监听整个对象的新增、删除、数组下标变更，惰性创建依赖（`WeakMap<target, Map<key, Set<effect>>>`）。
- 性能：Vue 3 按需追踪，初始化开销更小，嵌套深对象无需递归遍历。

### 2. Vue 3 中 `ref` 和 `reactive` 的区别？`toRef`、`toRefs` 有什么用？
**参考要点**
- `ref`：把基本类型或对象包成带 `.value` 的 ref 对象，对象内部仍会调用 `reactive`。
- `reactive`：仅代理对象，**整体替换会丢失响应式**。
- `toRef(obj, key)`：基于响应式对象的某个属性创建 ref，修改 ref 会同步到源对象。
- `toRefs(obj)`：把整个对象的每个属性都转成 ref，常用于解构 `setup` 返回值而不丢失响应式。

### 3. 说说 Vue 的 `nextTick` 原理和作用
**参考要点**
- 作用：在下次 DOM 更新循环结束之后执行回调，常用于"数据变了之后拿到最新 DOM"。
- 原理：把回调推到微任务队列（Vue 3 用 `queueMicrotask` / `Promise.resolve().then`），flush 时遍历 callbacks 数组执行。
- 同一事件循环多次修改响应式数据，watcher 会被去重，只在最后一个 nextTick 触发一次更新。

## 七、Node.js（2 题）

### 1. Node.js 中的事件循环和浏览器有什么不同？
**参考要点**
- Node 事件循环分阶段：`timers` → `pending callbacks` → `idle/prepare` → `poll` → `check` → `close callbacks`，每阶段之间会清空微任务队列和 `process.nextTick`。
- `setImmediate` 在 `check` 阶段执行，比 `setTimeout(fn, 0)` 在某些 I/O 回调中更"立即"。
- `process.nextTick` 优先级**高于** Promise 微任务，会形成"饥饿"，官方建议用 `queueMicrotask`。

### 2. 介绍一下 Stream 的四种类型及背压（backpressure）机制
**参考要点**
- 类型：`Readable`、`Writable`、`Duplex`、`Transform`。
- 背压：消费者消费速度低于生产者写入速度时，写入返回 `false`，生产者应暂停读取，直到 `drain` 事件触发。
- `pipe` 会自动处理背压；手写流时要用 `highWaterMark` 和 `drain` 控制速率。

## 八、浏览器与网络（3 题）

### 1. 从输入 URL 到页面渲染完成，浏览器都做了什么？
**参考要点**
1. URL 解析、DNS 解析（缓存 → 系统 → ISP → 根/顶级/权威 DNS）。
2. TCP 三次握手、TLS 协商（HTTPS 多了四次握手 + 加密）。
3. 发送 HTTP 请求，接收响应（304 走协商缓存）。
4. 解析 HTML 成 DOM 树，CSS 转 CSSOM，合并为 Render Tree。
5. 布局（Layout）、分层、绘制（Paint）、合成（Composite）→ 渲染到屏幕。
6. 加载过程中遇到 script / link / img 等资源继续请求，JS 会阻塞 DOM 解析（defer/async 除外）。

### 2. 强缓存和协商缓存分别是怎么实现的？
**参考要点**
- 强缓存：服务器通过 `Cache-Control: max-age=xxx` 或 `Expires` 设置过期时间；命中直接读本地，不发请求。
- 协商缓存：`Last-Modified` + `If-Modified-Since`（秒级）或 `ETag` + `If-None-Match`（内容哈希）；命中返回 304。
- `Cache-Control: no-cache` 不代表不缓存，而是**每次都要协商**；`no-store` 才真正不缓存。

### 3. 跨域是什么？CORS 怎么解决？JSONP 又是什么原理？
**参考要点**
- 跨域：浏览器同源策略限制，协议/域名/端口任一不同即跨域。
- CORS：服务器设置 `Access-Control-Allow-Origin`（简单请求直接放行；非简单请求会先发 OPTIONS 预检）。
- JSONP：利用 `<script>` 不受同源限制，通过 `?callback=xxx` 让后端把数据塞进函数调用里执行，仅支持 GET，已逐渐被 CORS 取代。

## 九、性能优化（2 题）

### 1. 首屏加载慢，你会从哪些方面排查和优化？
**参考要点**
- 网络：开启 gzip/Brotli、HTTP/2、CDN、资源合并/按需加载、preload/preconnect。
- 资源：图片懒加载、webp、雪碧图、字体子集化、关键 CSS 内联。
- 渲染：SSR/SSG、Suspense + lazy、骨架屏、避免长任务、React 18 `useTransition` 标记非紧急更新。
- 监控：用 Lighthouse、Web Vitals（LCP/FID/CLS）定位瓶颈，Performance 面板分析主线程火焰图。

### 2. 什么是 Web Vitals？LCP/FID/CLS 分别代表什么？
**参考要点**
- LCP（Largest Contentful Paint）：最大内容绘制时间，衡量加载性能，< 2.5s 算良好。
- FID（First Input Delay）：首次输入延迟，衡量交互性，< 100ms 良好（已被 INP 逐步替代）。
- CLS（Cumulative Layout Shift）：累计布局偏移，衡量视觉稳定性，< 0.1 良好。
- 优化：LCP 关注首屏资源优先级、CDN；FID 关注长任务拆分；CLS 要给图片/广告/动态插入元素固定宽高。

## 十、工程化（2 题）

### 1. Webpack 的构建流程大致是怎样的？有哪些核心概念？
**参考要点**
- 流程：初始化参数 → 加载插件 → 解析入口 → 递归构建依赖图 → 调用 Loader 处理各模块 → 封装 chunk → 优化（Tree Shaking、Code Splitting、压缩）→ 输出到 `dist`。
- 核心：entry、output、loader、plugin、mode、module、chunk、bundle、tree shaking、code splitting。
- 优化点：splitChunks 拆包、持久化缓存 (`cache: { type: 'filesystem' }`)、swc/esbuild 替换 babel。

### 2. Vite 为什么比传统打包器开发体验快？
**参考要点**
- 基于浏览器原生 ESM，开发时**不打包**，按需通过 HTTP 提供源码。
- 依赖预构建：启动时用 esbuild 把 CommonJS/UMD 依赖转成 ESM 并合并，减少请求数。
- HMR 基于 ESM 边界，模块更新只失效其父链，不刷新整页。
- 生产构建仍用 Rollup 做 tree shaking 和 code splitting。

## 十一、安全（2 题）

### 1. XSS 是什么？有哪些类型？如何防御？
**参考要点**
- 类型：存储型（恶意脚本入库）、反射型（URL 参数注入）、DOM 型（前端 `innerHTML` 等）。
- 防御：输入过滤 + 输出转义（React 已默认转义）、`Content-Security-Policy` 限制脚本来源、`HttpOnly` cookie 防止脚本读取、关键操作加 CSRF Token、避免 `eval`/`new Function`/`v-html`。

### 2. CSRF 攻击的原理和防御方案
**参考要点**
- 原理：用户已登录站点 A，被诱导访问恶意站点 B，B 利用 A 的 cookie 自动发起跨站请求。
- 防御：SameSite Cookie（`Lax`/`Strict`）、CSRF Token（每次请求携带）、Origin/Referer 校验、关键操作加二次验证（短信/密码）。

## 十二、移动端 / 小程序（2 题）

### 1. 移动端 1px 边框问题是怎么产生的？怎么解决？
**参考要点**
- 原因：高 DPR 设备上，CSS 的 1px 对应多个物理像素，且 `devicePixelRatio` 多数为 2 或 3。
- 方案：
  - `transform: scale(0.5)` + `transform-origin`，伪元素实现。
  - `box-shadow: 0 0 0 0.5px`。
  - 直接使用 `border-image` 配合 SVG 渐变。
  - 新方案：`@media (resolution: 2dppx) { border-width: 0.5px }`（iOS 支持良好，Android 参差）。

### 2. 小程序和 H5 的主要区别是什么？
**参考要点**
- 渲染：双线程（逻辑层 JSCore + 渲染层 WebView），通过 JSBridge 通信。
- API：受限的浏览器环境，没有 DOM/BOM，需用小程序自己的组件和 API。
- 性能：包大小限制（主包 2M）、分包加载、原生组件层级。
- 体验：接近原生，可调用扫码、定位、支付等系统能力，有自己的生命周期和路由栈。
