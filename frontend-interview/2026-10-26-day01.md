## 1. HTML（3 题）

### Q1. HTML 的 `src` 和 `href` 属性有什么区别？
**参考要点**
- `href` 是「引用」语义：用于 `<a>`、`<link>`、`<base>`，资源与当前文档相对独立，加载失败不影响文档解析。
- `src` 是「嵌入 / 替换」语义：用于 `<script>`、`<img>`、`<iframe>`、`<video>`、`<audio>`、`<embed>`、`<source>`，浏览器解析到即发起请求并**替换当前元素**，失败会破图或报错。
- `<script src>` 的加载时机由 `async` / `defer` 控制；`<img src>` 失败会触发 `error` 事件，可做兜底图。

### Q2. `<script>` 标签中 `defer` 和 `async` 有什么区别？
**参考要点**
- 默认（无属性）：同步脚本，下载与执行都会阻塞 HTML 解析。
- `defer`：并行下载，**文档解析完成后**按出现顺序执行，不阻塞解析。
- `async`：并行下载，**下载完立刻执行**，多个 async 脚本之间不保证顺序。
- `<script type="module">` 默认等同 `defer`（且强制 CORS、作用域隔离、支持顶层 await）。
- 仓库关联：站点 HTML 模板见 `src/pages/document.ejs`。

### Q3. 什么是 HTML 语义化？它的价值在哪？
**参考要点**
- 用语义正确的标签表达内容含义（`header/nav/main/article/section/aside/footer/button/label`），而不是全用 `div`。
- 收益：SEO（搜索引擎按语义解析）、无障碍（读屏软件依赖语义树）、可维护性（样式解耦，改样式不动结构）。
- 注意：语义标签自带默认样式与交互语义（如 `button` 自带 disabled 与表单提交行为），不要为了样式滥用。
- 来源：[HTML 的 src 和 href 属性有什么区别？](https://www.mianshiya.com/bank/1810644197003362306)

## 2. CSS（3 题）

### Q1. 如何计算 CSS 的优先级（层叠）？
**参考要点**
- 权重口诀：内联 `style` 1000 > id 100 > class / 伪类 / 属性选择器 10 > 标签 / 伪元素 1；`!important` 最高，且内联 `!important` > 外部 `!important`。
- 同权重时看**源码顺序**，后者覆盖前者。
- `@layer` 引入层叠层，未分层样式优先级高于已分层样式；`!important` 的层叠顺序与普通相反。
- `:is()/:not()/:has()` 参数中只取**最高**权重，`:where()` 恒为 0（用于「零权重」重置）。

### Q2. 说说你对盒模型的理解。
**参考要点**
- 标准盒模型 `content-box`（width 只算内容区）与 `border-box`（width 含 padding + border）；`box-sizing` 可全局重置。
- 外边距折叠：相邻兄弟之间、父元素与首/末子元素之间、空元素自身上下 margin 会折叠；BFC（`overflow: hidden`、`display: flow-root`、`flex/grid` 容器、`border/padding`）可阻止折叠。
- 百分比 padding/margin 相对**包含块的宽度**计算（与 font-size 无关）。

### Q3. `display: none` 与 `visibility: hidden` 的区别？
**参考要点**
- `display: none`：不生成盒子、不占布局空间、不渲染、不可被 `transition` 过渡（需配合 `visibility` 或 `@starting-style`）。
- `visibility: hidden`：保留盒子占位，子元素可用 `visibility: visible` 重新显示；可被过渡。
- 两者都只是「视觉隐藏」，读屏软件仍可能读到，彻底隐藏需 `aria-hidden` / `hidden` 属性。
- 来源：[利用 CSS 隐藏元素的方法有哪些？](https://www.mianshiya.com/bank/1810644318667538433)

## 3. JavaScript 基础（3 题）

### Q1. JavaScript 有哪些数据类型？它们的区别是什么？
**参考要点**
- 7 种原始类型：`string / number / boolean / undefined / null / symbol / bigint` + 引用类型 `object`（数组、函数也是 object）。
- 原始类型不可变、按值传递；object 按引用传递。
- `typeof null === 'object'` 是历史遗留 bug；`typeof` 对函数返回 `'function'`。
- `number` 是 IEEE 754 双精度浮点，整数安全范围 ±2^53-1。

### Q2. `typeof` 和 `instanceof` 有什么区别？
**参考要点**
- `typeof` 返回字符串，只能粗略判断；对 `null` 返回 `'object'`，对数组也返回 `'object'`。
- `instanceof` 判断「原型链上是否存在某构造函数的 prototype」，右值必须是函数（否则 `TypeError`）。
- `instanceof` 跨 iframe / 跨 realm 失效；判断数组应用 `Array.isArray`，判断原始类型用 `typeof`。

### Q3. 为什么 `0.1 + 0.2 !== 0.3`，如何让它们相等？
**参考要点**
- 原因：二进制无法精确表示 0.1 / 0.2（实际为 0.10000000000000000555…），IEEE 754 舍入误差。
- 方案：`Math.round(x * 100) / 100`（注意浮点乘 100 也可能有误差，金额建议用整数分）；`toFixed(2)` 返回字符串；用 `EPSILON` 容差比较。
- 反模式：不要用 `==` 兜底。

## 4. ES6 / 现代 JavaScript（3 题）

### Q1. ES6 箭头函数和普通函数有什么区别？
**参考要点**
- `this` 绑定：箭头函数不绑定 `this`，取定义处的词法作用域；不能用 `call/apply/bind` 改写。
- 没有 `arguments`（用剩余参数 `...args`）、不能 `new`、没有 `prototype`、不能作为 generator。
- `return` 对象时是普通对象，而非新构造的实例。
- 适用：回调、数组方法；慎用：对象方法、需要动态 `this` 的地方。

### Q2. ES Module 与 CommonJS 模块方案有什么异同？
**参考要点**
- 加载时机：ESM 静态分析、编译期确定依赖（可 Tree Shaking）；CJS 运行时 `require`、动态。
- 导出语义：ESM 是**实时绑定**（只读、可被内部修改）、顶层 `await`；CJS 导出的是 `module.exports` 对象上的属性（赋值语义）。
- 浏览器原生支持 `<script type="module">`（默认 defer、强制 CORS、严格模式）；CJS 需打包器。
- 混用坑：ESM 中没有 `__dirname`（需 `import.meta.url`）、ESM 导入 CJS 只能拿到 `default`。

### Q3. ES6 的 `Proxy` 可以实现什么功能？
**参考要点**
- 13 个 trap：`get/set/has/deleteProperty/ownKeys/defineProperty/getPrototypeOf/apply/construct/...`。
- 相比 `Object.defineProperty` 的优势是**拦截**能力：虚拟属性、拦截数组 `length`、函数 `apply`、代理对象整体。
- 典型场景：Vue3 响应式、埋点/日志拦截、只读包装（`Proxy` + `Reflect`）、Mock。
- 限制：无法代理 `Map/Set` 的内部槽方法、代理对象 `!==` 目标对象（可被检测）。

## 5. JavaScript 进阶（3 题）

### Q1. 什么是 JavaScript 的闭包？有什么作用和使用场景？
**参考要点**
- 定义：函数与其**词法环境**的组合；函数返回后仍能访问外层变量。
- 场景：私有变量/计数器、柯里化、防抖节流、事件监听、模块模式、`for` 循环中 `var` 的经典陷阱。
- 代价：闭包引用的对象无法被回收，滥用会造成内存驻留。

### Q2. 什么是 JavaScript 的原型链？终点是什么？
**参考要点**
- 每个对象有内部槽 `[[Prototype]]`，属性查找沿链向上，直到 `null`。
- 终点：`Object.getPrototypeOf(Object.prototype) === null`；`Object.create(null)` 的对象没有原型。
- `constructor` 挂在 `prototype` 上；`class` 是构造函数的语法糖（方法不可枚举、`prototype` 属性不可写）。

### Q3. 什么是 JavaScript 的事件轮询（事件循环）机制？
**参考要点**
- 顺序：调用栈 → **微任务队列**（`Promise.then`、`queueMicrotask`、`MutationObserver`）→ **宏任务**（`setTimeout`、I/O、UI 事件）→ 渲染。
- 每个宏任务结束后会把微任务队列**全部清空**，然后才可能渲染。
- Node 端：`process.nextTick` 优先于 Promise 微任务；`setImmediate` 在 check 阶段。
- 浏览器渲染发生在宏任务之间；`requestAnimationFrame` 在渲染前执行。

## 6. TypeScript（3 题）

### Q1. TypeScript 的类型别名和接口有什么区别？
**参考要点**
- `interface` 可以**声明合并**、可以被 `extends`、可用索引签名、类可 `implements`。
- `type` 可以是联合 / 交叉 / 条件 / 映射类型，但不能重复声明合并。
- 对象类型优先 `interface`，需要联合或工具类型时用 `type`。
- 两者在「对象结构」上几乎等价，性能上 `interface` 略优（可被缓存）。

### Q2. 什么是 TypeScript 的泛型？
**参考要点**
- 泛型 = 类型参数 + 约束（`T extends U`）+ 默认值（`T = string`）+ 推断（从实参推导）。
- 常用工具类型：`Partial / Required / Pick / Omit / Record / ReturnType / Parameters`。
- 典型场景：泛型函数、泛型接口、泛型 React 组件（`<T,>` 在 `.tsx` 中注意与 JSX 歧义）。
- 仓库关联：仓库大量使用泛型接口，例如 `src/services/question.ts` 的 `QuestionSearchParams`、组件的 `Props` 定义。

### Q3. `unknown` 和 `any` 有什么区别？
**参考要点**
- `any`：关闭类型检查，且会「传染」给所有推断结果。
- `unknown`：是 `any` 的安全版——不能直接赋给别的类型（除 `unknown`/`any`），必须先收窄。
- 推荐：外部输入（接口返回）用 `unknown` + 类型守卫，再用 `as` 断言。

## 7. React 基础（3 题）

### Q1. 为什么在 React 中遍历时不建议使用索引作为唯一的 `key`？
**参考要点**
- `key` 用于 diff 时标识节点身份；用 index 在插入/删除/重排时身份错位。
- 后果：无状态组件被错误复用（状态跑到别的行）、动画错乱、非受控输入值串行。
- 正确做法：用稳定唯一的业务 id；必要时用 `useId`。

### Q2. React 的 JSX 中，属性是否可以被覆盖？覆盖的原则是什么？
**参考要点**
- JSX 编译为 `createElement(type, config)` / `jsx(type, props)`，最终是**对象合并**。
- 规则：后面的覆盖前面的，展开运算符位置决定谁赢（`{...props}` 在前 → 显式属性覆盖它；在后 → 展开覆盖显式属性）。
- 注意 `className`（不是 `class`）、`htmlFor`（不是 `for`）、`style` 必须是对象。
- 函数组件的默认值推荐用默认参数（本仓库 `DebounceSelect` 即此写法），`defaultProps` 对函数组件已不推荐。

### Q3. 如何在 React 项目中引入图片？哪种方式更好？
**参考要点**
- 方式：`import img from './a.png'`（构建器转成 URL + 处理资源）、`require`、CSS 中 `url()`、放 `public` 用绝对路径。
- 打包器策略：小图（< 约 8KB）base64 内联减少请求，大图用 `file-loader/asset module` 输出带 hash 的独立文件。
- 优化：`srcset/sizes` 响应式、webp/avif、CDN 裁剪、懒加载。
- 仓库关联：`src/assets/logo.png`、`public/logo.png` 两种用法并存。

## 8. React 进阶（3 题）

### Q1. React 中 `setState` 的批量更新过程是什么？
**参考要点**
- `setState` 不立即改状态，而是把更新加入队列；在渲染阶段按队列重新计算。
- React 17 只在 React 事件回调内批处理，React 18 起**自动批处理**（含 Promise、定时器）。
- 多个 `setState` 合并：对象形式浅合并，**函数式 updater** 基于最新 state 计算。
- `setState` 在 `useEffect`/异步回调里等价于「立即触发一次渲染」，不要用来做同步取值（用 `useRef`）。

### Q2. React 的虚拟 DOM 和 Vue 的虚拟 DOM 有什么区别？
**参考要点**
- React：运行时全量 diff，组件级比较，React 18 引入并发渲染与自动批处理。
- Vue 2：模板编译成 render 函数，编译期做静态标记，patch 时跳过静态节点；Vue 3 用 Proxy + Block Tree 粒度更细。
- 相同点：都是「用 JS 描述 UI → diff → 最小化 DOM 操作」。

### Q3. React 组件间共享数据的方法有哪些？
**参考要点**
- 自上而下：`props`；状态提升（`useState` 上移到共同父级）。
- 跨层级：`Context`（主题、i18n、路由）——注意 Context 值变化会让所有消费者重渲染，需拆分 Provider / 用 `useMemo`。
- 全局状态：Redux / Zustand / MobX；服务端状态：React Query / SWR。
- 事件通信：mitt / 自定义事件总线。
- 仓库关联：本仓库用 UmiJS 的 `useModel` + `access` 做全局状态与权限，见 `src/access.ts`。

## 9. Vue 基础（3 题）

### Q1. Vue 的 `v-show` 和 `v-if` 有什么区别？使用场景分别是什么？
**参考要点**
- `v-if` 真正创建/销毁组件与子树（切换成本高），适合** seldom 切换**、权限控制。
- `v-show` 始终渲染，只切换 `display`（首次渲染成本高），适合**频繁切换**。
- `v-if` 可与 `v-else` / `v-else-if` 配合。

### Q2. 为什么不建议在 Vue 中同时使用 `v-if` 和 `v-for`？
**参考要点**
- Vue 2：`v-for` 优先级更高，每轮迭代都要重新求值 `v-if` 条件，浪费性能。
- Vue 3：`v-if` 优先级更高，`v-if` 里拿不到 `v-for` 的作用域变量。
- 最佳实践：先用 `computed` 过滤数据；或把 `v-if` 提到外层包裹元素上。

### Q3. 为什么 Vue 中的 `data` 属性是一个函数而不是一个对象？
**参考要点**
- 组件实例化时 `data` 以函数调用并返回新对象，保证**每个实例数据独立**；若返回同一对象，多个实例会互相污染状态。
- 根实例（`new Vue({ data: {...} })`）可以是对象，因为只有一个实例。

## 10. Vue 进阶（3 题）

### Q1. Vue 中 `nextTick` 的实现原理是什么？
**参考要点**
- 数据变更后，渲染调度器把更新任务推到微任务队列（Vue3 用 `Promise.then`，Vue2 用 `Promise/MutationObserver/setImmediate/setTimeout` 降级）。
- `nextTick` 回调在**组件 DOM 更新之后**执行，常用于「改完数据立刻读 DOM / 操作第三方实例」。
-  Vue 3 中 `nextTick` 返回 Promise，可 `await nextTick()`。

### Q2. DIFF 算法的原理是什么？
**参考要点**
- 同层比较 + `key` 判断身份：`key` 相同则 patch，不同则卸载重建。
- 四类比较：文本节点、属性/class/style、子节点列表、其它。
- 优化：双端 diff + 中间序列用**最长递增子序列（LIS）** 计算最小移动次数。
- 没有 `key` 时退化为按索引比较，会出现「错误复用」。

### Q3. Vue Router 的核心实现原理是什么？
**参考要点**
- history 模式：`pushState/replaceState` 改地址 + `popstate` 监听前进后退；hash 模式用 `hashchange`。
- 核心：路由表 → 路径匹配 → 渲染对应组件；`beforeEach/afterEach` 全局守卫 + 组件内守卫。
- 动态路由：登录后 `addRoute` 注入；404 用通配符 `/:pathMatch(.*)*`。
- 对应 React Router / UmiJS 路由配置，见仓库 `config/routes.ts`。

## 11. Node.js（3 题）

### Q1. Node.js 中，同步和异步代码有什么区别？
**参考要点**
- 同步阻塞事件循环；异步把 I/O 交给 libuv 线程池/事件循环处理，不阻塞主线程。
- JS 主线程仍是单线程，异步 ≠ 多线程（CPU 密集需 worker_threads / cluster）。
- `try/catch` 只能捕获同步异常，异步错误要靠回调 `err` 参数或 `unhandledRejection`。

### Q2. 在 Node.js 中，如何导入和导出模块？
**参考要点**
- CommonJS：`require` / `module.exports` / `exports`，有模块缓存（同一路径只执行一次）。
- ESM：`import/export`、顶层 `await`、需 `"type": "module"` 或 `.mjs`；`import()` 动态导入返回 Promise。
- 互操作：ESM 导入 CJS 只能拿到 `default`（即 `module.exports`），具名导入需借助静态分析。

### Q3. 什么是 Node.js 全局对象？有哪些常用的全局对象？
**参考要点**
- `global` 是全局对象；`process`（`env/argv/nextTick/exit/cwd`）、`Buffer`、`console`、`setTimeout/setImmediate`、`__dirname/__filename`（仅 CJS）。
- ESM 中 `__dirname` 不可用，用 `import.meta.url` + `fileURLToPath`。
- 仓库关联：后端 `server/src/server.js` 使用 `process.env.NODE_ENV` 区分环境。

## 12. Node.js 框架（Koa / Express）（3 题）

### Q1. Koa 的中间件机制是如何实现的？其底层原理是什么？
**参考要点**
- 洋葱模型：`await next()` 之前是「请求阶段」，之后是「响应阶段」。
- `koa-compose` 把多个中间件递归组合成一个 Promise 链。
- `ctx` 委托了 `req`/`res` 的属性代理，统一挂载 `state/body/cookies/query` 等。

### Q2. Koa 如何处理异步错误？底层是如何实现的？
**参考要点**
- 每个 `await` 都要放在 `try/catch` 中，`catch` 后 `ctx.throw` 或 `ctx.status = 500`。
- `compose` 在递归调用时捕获错误并沿链向上冒泡，最终交给最外层 `app.on('error')`。
- 对比 Express：Express 用 `next(err)` 跳转到 4 参数错误中间件。

### Q3. Express 的中间件是如何工作的？如何用它实现鉴权与统一错误处理？
**参考要点**
- `app.use(path, fn)` 按注册顺序执行，签名 `(req, res, next)`；`next()` 推进、`next(err)` 交给错误中间件（4 个参数）。
- 鉴权中间件：校验 session / token，通过则 `next()`，否则 `res.status(401).end()`。
- 统一错误处理放最后注册，捕获 `err` 并返回统一 JSON 结构。
- 仓库关联：`server/src/server.js` 用 Express 中间件串起 CORS、Session（Redis 存储）、统一异常处理；但 `Access-Control-Allow-Origin` 直接回显 `req.get('Origin')` 且允许携带凭证，存在 CSRF 风险，应改为白名单校验。

## 13. 手写代码（3 题）

### Q1. 如何实现防抖函数 `debounce`？
**参考要点**
- 基础版：`setTimeout` + `clearTimeout`，`wait` 内无调用则真正执行。
- 进阶：支持 `immediate`（首次立即执行）、返回 `cancel()` / `flush()`。
- 注意：需要 `this` 与参数透传；闭包保存 timer id。
- 仓库关联：`src/components/DebounceSelect/index.tsx` 使用 `lodash/debounce`，并用 `fetchRef` 递增的 `fetchId` 丢弃过期响应（竞态处理），面试可延伸讨论「防抖 + 竞态 + 取消请求」。

### Q2. 如何使用 JS 实现发布订阅模式？
**参考要点**
- 核心 API：`on/off/emit`（支持多个回调、`once`、事件名数组、`off` 移除全部）。
- 实现要点：事件名 → 回调列表的映射（用 `Map` 或对象），`emit` 时拷贝一份回调列表再遍历（避免回调中 `off` 导致遍历错乱）。
- 与观察者模式区别：发布订阅解耦发布者与订阅者；典型实现 `mitt`、`EventEmitter`、Vue 2 的事件总线。

### Q3. 如何在 JS 中实现继承（用尽可能多的方式）？
**参考要点**
- 方式：原型链继承 `Object.create(parent.prototype)`；构造函数 + `call/apply` 借用；**寄生组合继承**（`Parent.call(this)` + `Object.create`）——推荐。
- ES6：`class Child extends Parent` + `super()`（内部就是原型链 + 构造函数借用）。
- 其他：`Object.assign` 浅拷贝组合、`mixin`（混入多个方法的组合模式）。
- 注意：`instanceof` 依赖原型链；`Object.create(null)` 的实例不满足 `instanceof`。

### Q1. 什么是前端工程化？它有什么意义？
**参考要点**
- 范畴：项目初始化（脚手架）、规范（ESLint / Stylelint / Prettier / EditorConfig）、构建（UmiJS / Webpack / Vite）、依赖管理（npm/yarn/pnpm + lockfile）、CI/CD 与部署（Docker + Nginx）、监控与埋点。

### Q2. `export`、`export default` 和 `module.exports` 有什么区别？
**参考要点**
- ESM：具名导出 + 默认导出；导出的是**实时绑定**（只读），`import` 来的绑定不能重新赋值。
- CJS：`module.exports` 是一个对象，`exports` 是它的初始引用；给 `exports.foo = x` 等价于 `module.exports.foo = x`，但**给 `module.exports` 整体赋值后 `exports` 失效**。

### Q3. 如何使用 Docker 部署前端项目？

- `.dockerignore` 排除 `node_modules`；用 ARG/ENV 区分环境变量。
- Nginx：`gzip` 压缩、静态资源强缓存 + `index.html` 不缓存、SPA 路由 `try_files $uri /index.html`。
- 仓库关联：根目录 `Dockerfile` + `docker/nginx.conf` 可直接作为对照；`cloudbaserc.json` 是另一条腾讯云开发部署链路。

## 15. Webpack（3 题）

### Q1. 什么是 Webpack？它有什么作用？
**参考要点**
- 静态资源打包器：从入口出发构建依赖图，经 loader 转换、打包插件处理后输出产物。
- 四大概念：entry / output / loader / plugin。
- 生态地位：UmiJS 3 底层基于 Webpack；Vite 开发期用 esbuild + 原生 ESM，生产用 Rollup。

### Q2. Webpack 中 `CSS-Loader` 和 `Style-Loader` 有什么区别？
**参考要点**
- `css-loader`：把 CSS 转成 JS 模块（可被 `import`），解析 `@import`、处理 `url()`。
- `style-loader`：把 CSS 以 `<style>` 注入页面（运行时注入，不产生额外请求，但无法做 CSS 缓存）。
- 生产：`mini-css-extract-plugin` 抽成独立 `.css` 文件（利于长期缓存）+ `css-minimizer` 压缩。
- 仓库关联：项目样式使用 Less（`src/**/*.less`），需 `less-loader` + `less` 链。

### Q3. Webpack 中的 `publicPath` 有什么作用？生产环境如何优化产出代码？
**参考要点**
- `publicPath` 决定运行时**动态加载资源**的公共前缀（CDN 域名、绝对路径、`auto`）。
- 优化手段：拆分 `vendor` chunk（`splitChunks`）、`contenthash` 配强缓存、`sideEffects` + Tree Shaking、`terser` 压缩、`babel` 按 `browserslist` 降级、gzip/brotli、生产关闭 source map、移除 `console`（仓库已依赖 `babel-plugin-transform-remove-console`）。

## 16. 性能优化（3 题）

### Q1. 如何使用 Webpack 进行高效分包优化？
**参考要点**
- `splitChunks.chunks: 'all'` + `cacheGroups`（`vendors` / `node_modules` / 公共组件）。
- 路由级懒加载 `import()` 动态分包，配合 `webpackChunkName` 注释固定文件名。
- 首屏只加载必要 chunk，`preload`/`prefetch` 预取下一屏资源。

### Q2. 如何优化 Webpack 打包后文件的体积？
**参考要点**
- 先分析：`webpack-bundle-analyzer` 找大依赖。
- 手段：Tree Shaking（`sideEffects: false`）、按需引入（`babel-plugin-import`）、替换重依赖（`moment` → `dayjs`）、图标按需、压缩（terser + gzip/brotli）、避免把大库整体引入。

### Q3. 在网页中有大量图片时，如何优化图像加载以提高页面加载速度？
**参考要点**
- `loading="lazy"` / `IntersectionObserver` 懒加载；首屏关键图用 `preload`。
- 响应式：`srcset` + `sizes`；现代格式 webp/avif；CDN 图片裁剪。
- 小图标用 SVG 或 base64 内联；固定宽高（或 `aspect-ratio`）避免 CLS。
- 雪碧图 / 字体图标化，减少请求数。

## 19. 代码分析（2 题）

### Q1. 下面代码的输出顺序是什么？为什么？
```js
console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
(async () => {
  console.log('D');
  await null;
  console.log('E');
})();
console.log('F');
```
**答案**：`A D F C E B`
**解析**：同步代码先执行 → `A`、`D`（async 函数同步部分）、`F`；同步阶段结束清空微任务队列 → `C`（先入队）、`E`（`await null` 的续行后入队）；最后执行宏任务 → `B`。

### Q2. 下面代码的输出是什么？说明原因。
```js
var fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => i);
}
console.log(fns.map((f) => f())); // ?

for (let j = 0; j < 3; j++) {
  fns.push(() => j);
}
console.log(fns.map((f) => f()).slice(3)); // ?
```
**答案**：`[3, 3, 3]` 与 `[0, 1, 2]`
**解析**：`var` 在函数级作用域只有一个绑定 `i`，三个闭包共享同一变量，循环结束时 `i === 3`；`let` 每次迭代创建**新的块级绑定**，三个闭包各自持有 0/1/2（也正是 `for...of`/`forEach` 中 `let` 能正确捕获每轮值的原因）。

## 20. 本仓库实战（面试鸭站点源码）（3 题）

### Q1. `src/plugins/axios.js` 的请求封装有哪些可以改进的地方？
**参考要点**
- `baseURL` 用 `process.env.NODE_ENV` 判断，但仓库实际用的是 `UMI_ENV` / `REACT_APP_ENV`（见 `package.json` scripts），生产/测试环境区分不准确。
- `withCredentials = true` 会带上 Cookie，跨域时服务端必须回 `Access-Control-Allow-Credentials` 且 `Allow-Origin` 不能是 `*`。
- 响应拦截器只处理 401/403/500，其它业务 `code` 直接透传，缺少统一的错误对象与监控上报；网络错误与业务错误未区分。
- 缺少超时、请求取消（`AbortController`）、重试与防重复提交。
- 与 `src/utils/request.ts`（umi-request）存在**两套请求封装职责重叠**，建议收敛到一套。

### Q2. `src/wrappers/auth.tsx` 这个权限包裹组件有什么问题？UmiJS 推荐的写法是什么？
**参考要点**
- 在 render 阶段直接调用 `message.warning`：每次渲染都会弹一次，且 antd 的 message 会累积，应放到 `useEffect` 或改用 `Alert`。
- `Redirect` 触发整页跳转；UmiJS 更推荐 `history.push`（配合 `useLocation` 拿 `redirect` 参数并 `encodeURIComponent`）。
- `access` 来自 `src/access.ts`，只依据 `initialState.currentUser`；应在 `getInitialState` 里统一拉取用户信息并提供骨架/加载态，避免闪烁。

### Q3. `src/components/DebounceSelect` 的竞态是怎么处理的？还有哪些可优化点？
**参考要点**
- 竞态：`fetchRef.current += 1` 生成 `fetchId`，回调里比对 `fetchId !== fetchRef.current` 则丢弃过期响应——这是「只保留最后一次请求结果」的经典写法。
- 防抖：`lodash/debounce` + `useMemo` 依赖 `[fetchOptions, debounceTimeout]`，避免每次渲染重建定时器。
- 可优化：组件卸载时 `debounce.cancel()` + `AbortController` 取消在途请求；相同关键字结果缓存；补充 `error` 分支（当前只有 `fetching`，请求失败会一直显示空）；`options` 建议 `useState<OptionType[]>` 显式类型。
